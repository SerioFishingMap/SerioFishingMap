# 画面設計書（釣りマップ）

Webアプリ「釣りマップ」の各画面を、統一フォーマットで記述するための設計ドキュメント一式です。
1画面につき1ファイルを作成し、[screen-list.md](./screen-list.md) で一覧管理、[screen-transition.md](./screen-transition.md) で全体の遷移を可視化します。

## 目的
- 画面ごとの仕様（レイアウト・項目・操作・遷移）を関係者間で共有する
- 実装・レビュー・テストの共通の拠り所にする
- 表記ゆれを防ぎ、どの画面も同じ粒度・同じ語彙で書けるようにする

## ディレクトリ構成
| ファイル | 役割 |
| --- | --- |
| `README.md` | 本ファイル。使い方・命名規則・記法の凡例 |
| `_template.md` | 各画面設計書のテンプレート（コピー元） |
| `screen-list.md` | 画面一覧（全画面のインデックス） |
| `screen-transition.md` | 画面遷移図（Mermaid） |
| `SCR-XXX-*.md` | 各画面の設計書（テンプレをコピーして作成） |

## 新規画面を追加する手順
1. `_template.md` をコピーし、`SCR-XXX-<画面名>.md` にリネームする（命名規則は下記）。
2. 先頭の HTML コメント（記入ガイド）を消し、各セクションを埋める。
3. [screen-list.md](./screen-list.md) の一覧表に1行追加する。
4. [screen-transition.md](./screen-transition.md) に新しい画面ノードと遷移を追記する。
5. プルリクエストでレビューを受け、`ステータス` を更新する。

## 命名規則
### 画面ID
- 形式: `SCR-` + 3桁のゼロ埋め番号（例: `SCR-101`）。
- 機能グループごとに百の位で採番する（採番範囲はプロジェクトの実態に合わせて調整可）。

| 範囲 | 機能グループ（例） |
| --- | --- |
| `SCR-0xx` | 共通（ホーム・検索） |
| `SCR-1xx` | 釣果（一覧・詳細・登録・編集） |
| `SCR-2xx` | 魚図鑑 |
| `SCR-3xx` | 釣り場（一覧・地図・詳細） |
| `SCR-4xx` | **欠番**（釣行は画面を持たない。番号は再利用しない） |
| `SCR-5xx` | マスタ管理（マスタ追加） |

### ファイル名
- 形式: `SCR-XXX-<英小文字ハイフン区切り>.md`（例: `SCR-101-map.md`）。

## 記法の凡例
表記を統一するため、以下の語彙を使う。各画面設計書・一覧・遷移図で共通とする。

### ドメイン用語
日本語・英語（コード上の型名／識別子）・URL の対応。**設計書の語彙を正とする**。

| 日本語 | 英語（コード） | URL |
| --- | --- | --- |
| 釣果 | `Catch` | `/catches` |
| 魚 | `Fish` | `/fish` |
| 釣り場 | `Spot` | `/spots` |
| 釣行 | `Trip` | **なし**（画面を持たない） |

- 同行者・タックル・道具・水況の 4 概念は用語未確定（[docs/tasks.md](../tasks.md) の T-23 で扱う）。
- **釣行（Trip）は専用画面を持ちません。**釣果登録画面（SCR-103）から入力したデータを釣行記録として保存し、必要な情報のみを各画面で使用します。データモデルとしては存続します（[CLAUDE.md](../../CLAUDE.md) の「ドメインモデル」）。

### 権限の扱い（2026-08-26 時点：保留）
**ログイン・ログアウトは当面実装しない**（[docs/tasks.md](../tasks.md) の D-06）。ユーザー登録の要否が未検討で、UI にも含まれていないため。

- したがって **すべての画面の対象ユーザーは `全ユーザー`**。「未ログイン / 会員 / 本人」による出し分けは行わない。
- 各設計書に残る権限の記述は**削除せず、`保留` と明記して残す**。ログイン導入を再検討する際にそのまま使えるようにするため。
- 状態パターンの `権限なし` は当面使わない。

### ステータス
`下書き` → `レビュー中` → `確定` の3段階。

### 必須（画面項目）
`○`（必須） / `−`（任意）。

### 項目の種別
`ラベル` / `テキスト入力` / `数値入力` / `日付` / `選択（ドロップダウン）` / `チェックボックス` / `ラジオ` / `ボタン` / `リンク` / `画像` / `地図` / `一覧（テーブル）` / `その他`

### 画面の状態パターン
`通常` / `ローディング` / `データ空（Empty）` / `エラー` / `権限なし`

### メッセージ種別
`正常` / `確認` / `警告` / `エラー`

## 図・表について
- 図は [Mermaid](https://mermaid.js.org/) を使う（GitHub 上でそのまま描画され、外部画像が不要）。
- 表は GitHub Flavored Markdown のパイプ表。未記入セルは `（記入）` を残す。
- **画面レイアウトの正典は Figma**。各画面設計書の「3. 画面レイアウト」「1. 基本情報＞デザインカンプ」に対象フレームの URL を貼る。設計書側にレイアウト画像を二重管理しない。

### Figma からテキストを起こす手順

項目表（4.）・状態（6.）などのテキストは Figma フレームから起こす。**Figma REST API** を使う（Figma MCP は Starter プランで 6 コール/月 の制限があり、対話1往復ごとに消費するため使わない）。

- 対象ファイル: **セリオ釣りMAP**（file_key `LgJDTLLmkMfjeamo0zQl2b`）。キャンバスは `version1.0` と `version2.0` に分かれており、**`version2.0` が最新**。
- 画面と node-id の対応の正典は [screen-list.md](./screen-list.md) の**デザインカンプ列**。
- 認証は Personal Access Token（スコープ `file_content:read`、有効期限は最長 90 日）を `X-Figma-Token` ヘッダに載せる。**トークンは `.secrets/figma.env` に置く**（置き場所と扱い方の正典は [.claude/rules/secrets.md](../../.claude/rules/secrets.md)）。各メンバーが自分のトークンを発行すること。

  ```bash
  . /workspace/ymj-claude-exp/.secrets/figma.env
  curl -sS -H "X-Figma-Token: $FIGMA_TOKEN" https://api.figma.com/v1/me
  ```

- `GET /v1/files/:key?depth=2` でフレーム一覧、`GET /v1/files/:key/nodes?ids=...` でレイヤー構造を取得する。**`ids` はカンマ区切りで複数指定できる**ので、必ず 1 リクエストにまとめる。node-id は URL 形式の `1158-1649` ではなく**コロン形式 `1158:1649`** を渡す。
- Tier 1（上記2つと `GET /v1/images`）は **Starter プランで月 6 リクエスト**。取得した JSON はローカルに保存し、解析は保存済みファイルに対して行う（再取得しない）。
- 疎通確認は `GET /v1/me` を使う。Tier 3 なので**月6回の枠を消費しない**。

**この手順を実行する手段は [.claude/skills/figma-sync/SKILL.md](../../.claude/skills/figma-sync/SKILL.md)（スキル `figma-sync`）。** 枠を無駄にする事故（node-id の形式ミス・個別取得・キャッシュ保存漏れ・失効トークンでの取得）を防ぐため、**取得は手で `curl` を組まずスキルのスクリプト経由で行う**。本節は「何を叩くか」の正典、スキルは「どう安全に実行し、差分をどう設計書へ反映するか」を担当する。
